# hub-api

The employee AI hub's API, implemented: every path of `hub/api/openapi.yaml` plus `/shelf`, behind the bank's
identity provider, on the standard library. One process serves the API and the built hub, so the deployable is a
single container with a record file.

## What it does

| Area | Behaviour |
| --- | --- |
| Identity | `HUB_AUTH=oidc`: an RS256 JWT from the bank's identity provider, verified against its JWKS (signature, exp, nbf, iss, aud), mapped to roles, entitlements, teams and ladder by `data/identity-map.example.json` (group ids, owned by the platform team; its shape is checked at load and by `check-config`, and a claim of the wrong type is ignored or a 401, never a 500). A token needs a subject (`oid` or `sub`). `HUB_AUTH=mock`: `mock.<persona>` tokens for the five personas in `data/examples.json`; refused in staging and production |
| Catalog | The bank's own listings from `HUB_CONSUMERS_FILE` plus every component of the collection from `data/collection.json` (generated by `tools/shelf.py --write`); access resolved per person from entitlements, never typed by an owner |
| Briefs | The intake brief with the same six-section rules as the browser (`hubapi/briefs.py` mirrors `hub/src/api/schemas.ts`), etags with If-Match, the lead rule for write profiles, estimate and road |
| Requests, workspace, preferences | Persisted per person in the record; a request names a listing in the catalog and a known ladder (422 otherwise), preferences are the known keys with their types (422); briefs, preferences and turns take at most 64 KB a call (413), a conversation at most 200 turns (409 `conversation.full`; a turn adds two records, so the ceiling is never exceeded) and one turn streaming at a time (409 `conversation.busy`; the turn is written to the record as it is when the stream ends, never to a copy read before it). A view's `seq` is its position in the conversation, the same after a restart; feedback names a stored view (422 otherwise) |
| Conversations | Owned by the person and open only while their entitlement to the assistant holds (a revoked entitlement is 403 `entitlement.missing` on an existing conversation, its turns and its handoff). Turns stream as `event: view` server-sent events from one of three assistants: `fake` (development), `http` (relay to the platform runtime that owns the assistant, service credential by name), `bedrock` (answer here: sources from the knowledge base's search endpoint fenced by the guard, the model on Bedrock Converse in the cited engine's JSON shape, cite-or-drop, a tainted context stops before any model call) |
| The shelf | Sign-offs recorded against the version signed at; owner by name (and, with `HUB_OWNER_DOMAIN`, only from that email domain), AI security by role; every attestation required by the server; one sign-off per component, role and version (the check and the write are one locked section); two sign-offs are two people: the owner may not sign for AI security on their own component and a person who recorded one role at a version is refused the other (409 `shelf.duties`); `/shelf/signoffs/export` hands the file to `tools/shelf.py --apply-signoffs` so the commit is the signature |
| Static | `HUB_STATIC_DIR` serves the hub's `dist/` with an SPA fallback and immutable caching for assets |
| Record | SQLite at `HUB_DB` (WAL), a file in staging and production; idempotency replays are per person and per call (a key reused on another route is 422; a replay from before routes were recorded still replays); a key is claimed before its call runs, so a repeat while the first is still being answered is 409 `idempotency.in_progress` and two calls with one key never both execute. `backup <path>` opens the source read-only and refuses a `HUB_DB` that is not an existing file; `prune` applies the retention (conversations and replays) and prints both counts; a record from a newer build is one `record:` line and exit 2 |
| Health, logs | `/api/health` anonymous; logs carry ids and route templates only. Bodies are strict JSON (NaN and Infinity are 400 in, never out); a body on a page, an asset or `/config.js` is 405 and the connection closes (never read as the next request); an idle or stalled connection is dropped after 30 s, and a client that stops reading a stream is an abort (the turn is recorded with its stop view). `Content-Length` is one plain decimal (400 and close otherwise). SIGTERM stops accepting, drains the requests being answered for up to 25 s (an idle keep-alive connection is not in flight; a request arriving on one after the stop began is 503 and the connection closes), closes the record (the WAL is checkpointed away) and exits 0 |

## Run it

```
cd services/hub-api
python3 -m unittest discover -s tests -t .                    # 16 tests: the contract, OIDC through a generated key, the assistants
python3 -m hubapi check-config                                # exit 2 with every problem named, never a value
HUB_STATIC_DIR=../../hub/dist-http python3 -m hubapi serve    # sandbox: mock personas, the fake assistant, a memory record
```

Build the hub for it with `cd hub && VITE_API_MODE=http VITE_AUTH_MODE=mock pnpm exec vite build --outDir dist-http`
(sandbox) or `.env.production` from `hub/.env.production.example` (the bank's identity provider). Open
`http://localhost:8080/discover?mockPersona=gk`.

Against the bank's systems: `config/collection.env.example` names every variable; `CONFIGURATION.md` explains
each. The entrypoint runs `check-config` first and a live process with a missing gate never listens.

## Files

| File | What it is |
| --- | --- |
| `hubapi/settings.py` | Configuration that fails closed (the fail-closed-config pattern with this service's rules) |
| `hubapi/auth.py` | `OidcAuth`, `MockAuth`, `IdentityMap`, `Principal` |
| `hubapi/catalog.py` | Listings, details, workspace, the shelf's sign-off view |
| `hubapi/briefs.py` | The brief's rules, estimate and road |
| `hubapi/assistant.py` | `FakeAssistant`, `HttpRelayAssistant`, `BedrockAssistant` |
| `hubapi/store.py` | The record |
| `hubapi/app.py` | Routes, problems, idempotency, SSE, static, the server |
| `hubapi/vendor/` | Copies from components (`services/vendor.json`; `python3 services/vendor.py --check`) |
| `data/` | `collection.json` (generated), `consumers.example.json`, `identity-map.example.json`, `examples.json` (mock personas and design-canvas examples) |

## Replacing the example data

`consumers.example.json` is the design canvas transcribed: listings, one detail page, registry systems and
tools, the estimate and road texts, assistant metadata, workspace rows. The bank's records replace it at
`HUB_CONSUMERS_FILE`; the shape is the one the hub renders (`hub/src/api/types.ts`). `identity-map.example.json`
carries placeholder group ids; the platform team fills in the directory's.
